提问：战友，你好！你的避免重复的架构规划很详细，很棒！我们1.0确实没有Variant Planning和Diversity Gate，我看到你提到先做轻量“Variant Planning”，如果我们先对MVP做一次迭代，从1.0升级到1.5，来满足我们菲律宾运营团队的投手需求，请指定一个迭代的计划和实施步骤

回答：战友，这次 1.0 → 1.5 的迭代，目标不要定太大。**1.5 不是重做完整 Matrix Engine，而是给菲律宾运营团队补上“轻量 Variant Planning + Diversity Gate”，先解决批量生成一模一样视频的问题。**

一句话：

> **DopaMatrix 1.5 的核心目标：从“批量渲染 N 条”升级为“先规划 N 个有差异的变体，再并发渲染”。**

# 一、1.5 版本定位

## 1.0 当前状态

你们现在大概率是：

```text
用户设置 batch_size = 4
↓
系统循环生成 4 次
↓
每次用同一套 recipe / tags / matcher
↓
matcher 每次取相同 Top 1 素材
↓
生成 4 条一模一样视频
```

本质是：

> **批量渲染器，不是矩阵变体引擎。**

---

## 1.5 目标状态

升级后应该是：

```text
用户设置 batch_size = 4
↓
系统先生成 Matrix Plan
↓
Variant Planner 串行规划 4 个 Variant Plan
↓
Diversity Gate 检查每个变体是否重复
↓
写入 Batch Diversity Ledger
↓
生成 4 个不同 Render Intent
↓
再并发渲染
```

本质变成：

> **轻量矩阵规划器 + 并发渲染队列。**

---

# 二、1.5 不要做什么

为了 MVP 可落地，1.5 先不要做这些：

```text
暂不做 CLIP embedding 去重
暂不做 pHash 感知去重
暂不做完整情绪归因学习
暂不做复杂 MMR / Max-Min Diversity
暂不做跨 batch 全局疲劳控制
暂不做完整 Story DSL 2.0
暂不做全量 Semantic Timeline 重构
```

这些可以放到 2.0。

1.5 只做最实用的 5 件事：

```text
1. Variant Plan
2. Batch Diversity Ledger
3. Render Intent Hash
4. Opening 3s Signature
5. 候选不足提示
```

---

# 三、1.5 必须解决的核心问题

## 问题 1：同批次完全重复

解决目标：

```text
同一个 batch 内，不允许 render_intent_hash 完全相同。
```

也就是渲染指令完全一样时，直接拦截，不进入 FFmpeg。

---

## 问题 2：开头 3 秒重复

买量视频最关键是前 3 秒。

解决目标：

```text
同一个 batch 内，opening_signature 不允许重复。
```

opening_signature 可以先用简化版：

```text
opening_x_asset_id
+
hook_text_hash
+
opening_subtitle_style
+
opening_sticker_id
```

后面再升级为 pHash / 视觉相似度。

---

## 问题 3：X 轴主素材重复

解决目标：

```text
同一个 batch 内，x_primary asset_id 默认不重复。
```

如果候选素材不足，可以让投手选择放宽。

---

## 问题 4：asset_cluster 重复

1.5 可以先做轻量版 cluster。

不用上复杂 embedding，先用：

```text
同源文件
同一 episode + 时间段
同一文件 hash
人工标记 similar_group
```

得到：

```text
asset_cluster_id
```

规则：

```text
同一 batch 内，x_primary 的 asset_cluster_id 默认不重复。
```

---

## 问题 5：候选不足时硬凑数量

1.5 必须避免静默生成重复视频。

如果 batch_size = 4，但有效差异组合只有 2 个，就提示：

```text
当前去重规则下只能生成 2 条有效变体。
是否：
[生成 2 条]
[放宽素材限制]
[允许同素材不同 Hook]
[切换为轻微变体模式]
[补充素材]
```

这对菲律宾投手非常重要。

# 五、1.5 新增模块

建议新增 5 个轻量模块。

---

## 1. Matrix Plan

Matrix Plan 是本轮生成任务的总计划。

示例：

```json
{
  "batch_id": "batch_2026_001",
  "project_id": "ph_rpg_001",
  "recipe_id": "recipe_near_win_001",
  "batch_size": 4,
  "test_goal": "test_hook",
  "platform": "tiktok",
  "market": "philippines",
  "language": "taglish",
  "variation_strength": "medium",
  "diversity_policy": {
    "opening_3s_unique": true,
    "x_primary_asset_unique": true,
    "asset_cluster_unique": true,
    "hook_text_unique": true,
    "render_intent_unique": true,
    "cta_can_repeat": true,
    "bgm_can_repeat": true
  }
}
```

---

## 2. Variant Plan

Variant Plan 是每条视频的计划。

```json
{
  "variant_id": "v_001",
  "batch_id": "batch_2026_001",
  "variant_index": 1,
  "seed": "batch_001_v_001",
  "variation_axes": {
    "hook_type": "near_win_failure",
    "opening_asset_strategy": "unique_x_primary",
    "hook_text_strategy": "unique",
    "cta_type": "playable_try_now",
    "subtitle_style": "bold_taglish"
  },
  "fixed_axes": {
    "story_node": "boss_low_hp_fail",
    "emotion_arc": "frustration_to_retry",
    "platform": "tiktok",
    "language": "taglish"
  }
}
```

投手不需要看到完整 JSON，但后端要有这个对象。

---

## 3. Diversity Gate

Diversity Gate 负责拦截重复。

每个 Variant Plan 生成 Render Intent 前后，都要检查：

```text
是否 x_primary asset 重复？
是否 asset_cluster 重复？
是否 opening_signature 重复？
是否 hook_text 重复？
是否 render_intent_hash 重复？
是否素材使用超过本批次配额？
```

如果重复：

```text
重新采样
换素材
换 Hook
换 CTA
或者提示候选不足
```

---

## 4. Batch Diversity Ledger

账本记录本 batch 已经占用的东西。

```json
{
  "batch_id": "batch_2026_001",
  "used_x_primary_assets": ["asset_A", "asset_B"],
  "used_asset_clusters": ["cluster_001", "cluster_002"],
  "used_opening_signatures": ["sig_001", "sig_002"],
  "used_hook_text_hashes": ["hook_001", "hook_002"],
  "used_render_intent_hashes": ["render_001", "render_002"]
}
```

SQLite 落库，内存也保留一份。

---

## 5. Render Intent Hash

Render Intent 生成后，计算 hash。

hash 内容至少包括：

```text
template_id
recipe_id
beat_sequence
x_primary_asset_ids
y_layer_asset_ids
hook_text
subtitle_text
cta_text
bgm_id
sfx_ids
layout_style
duration_plan
```

如果 hash 一样，说明视频计划完全一样。

# 八、后端实施步骤

建议拆成 6 个小迭代。

---

## Sprint 1：加 variant_id、batch_id、独立 seed

目标：每条视频都有独立身份。

实施：

```text
1. 新增 matrix_batches 表
2. 新增 matrix_variants 表
3. 生成任务必须创建 batch_id
4. 每个视频生成 variant_id
5. seed = hash(batch_id + variant_index + recipe_id)
6. 输出文件名带 batch_id / variant_id
```

验收：

```text
批量生成 4 条时，数据库能看到 4 个不同 variant_id。
每条任务 seed 不同。
输出文件名不覆盖。
```

---

## Sprint 2：加 Render Intent Hash 去重

目标：完全一样的视频计划不进入渲染。

实施：

```text
1. 生成 render_intent_json
2. 对关键字段做标准化排序
3. 计算 render_intent_hash
4. 写入 matrix_variants
5. 如果同 batch 内 hash 重复，重新生成或报候选不足
```

验收：

```text
同一个 batch 内，不允许出现两个相同 render_intent_hash。
```

---

## Sprint 3：加 Batch Diversity Ledger

目标：同批次主素材不重复。

实施：

```text
1. 新增 batch_asset_reservations 表
2. Variant Planner 选中 x_primary 后，先写 reservation
3. 同 batch 内 used_x_primary_asset 不重复
4. 失败任务支持释放 reservation
5. 渲染成功后 reservation 状态变 rendered
```

验收：

```text
batch_size = 4 时，4 条视频 x_primary asset_id 不重复。
如果候选只有 2 个，系统只生成 2 个或提示放宽。
```

---

## Sprint 4：加 opening_signature

目标：开头 3 秒不重复。

实施：

```text
1. 定义 opening_signature
2. opening_signature = hash(opening_asset_id + hook_text + opening_sticker + subtitle_style)
3. 写入 matrix_variants
4. 同 batch 内 opening_signature 不重复
```

验收：

```text
4 条视频不能使用完全相同的开头素材 + Hook 文案组合。
```

---

## Sprint 5：加轻量 Variant Planner

目标：不是每条都随机，而是按测试目标规划差异。

实施：

```text
1. Matrix Lab 增加 test_goal
2. 根据 test_goal 生成 variation_axes
3. test_hook：Hook 文案和开头素材必须变化
4. test_cta：CTA 必须变化，Hook 可固定
5. light_variation：允许同素材但字幕/CTA/贴纸变化
6. strong_variation：Story Node / 主素材 / Hook 都尽量变化
```

验收：

```text
投手选择不同测试目标时，生成结果的差异点符合预期。
```

---

## Sprint 6：候选不足提示和失败兜底

目标：不要静默生成重复视频。

实施：

```text
1. 生成前计算候选容量
2. 如果有效组合 < batch_size，弹出提示
3. 支持放宽策略
4. 支持只生成有效数量
5. 支持进入素材缺口提示
```

验收：

```text
候选不足时，系统不再生成重复视频，而是提示原因和建议。
```

# 十一、核心伪代码

```python
def create_matrix_batch(recipe_id, batch_size, test_goal, policy):
    batch = create_batch(recipe_id, batch_size, test_goal, policy)

    candidate_pool = build_candidate_pool(recipe_id)

    valid_variants = []

    for index in range(batch_size):
        for attempt in range(10):
            variant_plan = plan_variant(
                batch=batch,
                index=index,
                test_goal=test_goal,
                candidate_pool=candidate_pool,
                seed=make_seed(batch.id, index, attempt)
            )

            render_intent = compile_render_intent(variant_plan)

            signatures = {
                "render_intent_hash": hash_render_intent(render_intent),
                "opening_signature": hash_opening(render_intent),
                "semantic_signature": hash_semantic(render_intent)
            }

            ok, reason = diversity_gate_check(
                batch_id=batch.id,
                variant_plan=variant_plan,
                render_intent=render_intent,
                signatures=signatures,
                policy=policy
            )

            if not ok:
                continue

            reserve_ok = reserve_variant_in_ledger(
                batch_id=batch.id,
                variant_plan=variant_plan,
                render_intent=render_intent,
                signatures=signatures
            )

            if reserve_ok:
                valid_variants.append(variant_plan)
                break

    if len(valid_variants) < batch_size:
        return {
            "status": "partial",
            "valid_count": len(valid_variants),
            "requested_count": batch_size,
            "reason": "candidate_not_enough"
        }

    enqueue_render_jobs(valid_variants)

    return {
        "status": "ready_to_render",
        "valid_count": len(valid_variants)
    }
```

# 十二、1.5 验收标准

你们这次迭代一定要有明确验收。

## 功能验收

```text
1. batch_size = 4 时，不再出现 4 条完全一样的视频。
2. 同 batch 内 render_intent_hash 不重复。
3. 同 batch 内 opening_signature 不重复。
4. 同 batch 内 x_primary asset_id 默认不重复。
5. 候选不足时会提示，而不是硬生成重复。
6. 每条视频能显示自己的差异点。
```

---

## 稳定性验收

```text
1. Tauri 端连续生成 10 个 batch 不崩溃。
2. SQLite 不出现 database is locked 频繁错误。
3. 渲染失败后 reservation 能释放或标记 failed。
4. 用户关闭客户端再打开，可以恢复 batch 状态。
5. 并发渲染不会导致素材账本重复写入。
```

---

## 投手体验验收

让菲律宾运营团队测 3 个场景：

```text
场景 1：素材充足
batch_size = 4，系统生成 4 条差异明显的视频。

场景 2：素材不足
batch_size = 4，但只有 2 个有效主素材，系统提示只能生成 2 条。

场景 3：测试 Hook
同一个 Story Node 下，4 条视频 Hook / 开头素材不同，但 CTA 可以相同。
```

他们能理解、能接受、能操作，就算 1.5 成功。

# 十五、最终建议

战友，这次 1.5 不要追求复杂算法，先把产品从：

```text
批量生成 4 次
```

升级成：

```text
规划 4 个变体，再生成 4 条视频
```

这就是质变。

DopaMatrix 1.5 的关键交付物应该是：

```text
Matrix Plan
Variant Plan
Diversity Gate
Batch Diversity Ledger
Render Intent Hash
Opening Signature
候选不足提示
```

一句话总结：

> **1.5 的核心不是让视频“随机不一样”，而是让菲律宾投手清楚地控制：这一批到底在测试什么、哪些地方必须不同、素材不够时为什么不能硬凑。**
