问题：战友，本次我们做1.5的升级和第九点有关联关系吗，请确认，我们只是想先把变体生成的重复问题解决，这里的菲律宾运营团队的默认配置，起到什么作用，哪里需要用到？

回答：战友，确认一下：**1.5 解决变体重复问题，和“菲律宾运营团队默认配置”有关联，但不是强依赖。**

更准确说：

> **Variant Planning + Diversity Gate 是核心能力。**
> **菲律宾运营团队默认配置只是这套核心能力的一组“预设参数”。**

也就是说，你们要先做的是通用能力，不是先做菲律宾模板。

---

# 一、这两者是什么关系？

可以分成三层：

```text
第一层：Matrix Engine 1.5 核心能力
Variant Planning / Diversity Gate / Batch Ledger / Render Intent Hash

第二层：Diversity Policy 参数
开头是否去重、主素材是否去重、Hook 是否去重、CTA 是否允许重复

第三层：菲律宾运营默认配置
菲律宾市场、Taglish、TikTok、batch_size=4、默认测试 Hook、中等变体强度
```

所以：

```text
核心能力 = 发动机
Diversity Policy = 发动机参数
菲律宾默认配置 = 给菲律宾投手准备的一套默认参数包
```

---

# 二、你们如果只想先解决“生成重复视频”，第九点不是必须做

1.5 MVP 最小闭环只需要这些：

```json
{
  "batch_size_default": 4,
  "test_goal_default": "test_hook",
  "variation_strength_default": "medium",
  "diversity_policy": {
    "opening_3s_unique": true,
    "x_primary_asset_unique": true,
    "asset_cluster_unique": true,
    "hook_text_unique": true,
    "render_intent_unique": true,
    "cta_can_repeat": true,
    "bgm_can_repeat": true
  }
}
```

你看，这里面其实不一定需要：

```json
"market": "philippines",
"language": "taglish",
"platform": "tiktok"
```

这些字段对“菲律宾投手日常操作”有帮助，但不是避免重复的必要条件。

真正防重复靠的是：

```text
opening_3s_unique
x_primary_asset_unique
asset_cluster_unique
hook_text_unique
render_intent_unique
Batch Diversity Ledger
Render Intent Hash
```

# 三、菲律宾默认配置到底起什么作用？

它的作用不是防重复算法本身，而是让菲律宾运营团队**不用每次手动配置一堆参数**。

比如菲律宾投手日常可能就是：

```text
目标市场：菲律宾
语言：Taglish
平台：TikTok
批量大小：4
默认测试：Hook
变体强度：中等
开头 3 秒必须不同
主素材必须不同
Hook 文案必须不同
CTA 可以重复
BGM 可以重复
```

如果没有默认配置，投手每次新建 Matrix 任务都要自己选：

```text
市场
语言
平台
batch size
测试目标
变体强度
去重规则
```

如果有默认配置，进入 Matrix Lab 后直接是：

```text
菲律宾游戏漫剧买量模板
默认 batch_size = 4
默认 test_goal = test_hook
默认 variation_strength = medium
默认去重规则已勾选
```

投手只需要点：

```text
[生成 4 条变体]
```

这就是默认配置的价值。

---

# 四、它会在哪里用到？

## 1. Matrix Lab UI 初始化

当投手打开 Matrix Lab，系统自动填好：

```text
市场：Philippines
语言：Taglish
平台：TikTok
批量：4
测试目标：测试 Hook
变体强度：中等
```

相当于 UI 默认值。

---

## 2. 创建 Matrix Plan 时

用户点“生成”后，后端会创建：

```text
Matrix Plan
```

这个 Matrix Plan 会读取默认配置：

```json
{
  "batch_size": 4,
  "test_goal": "test_hook",
  "variation_strength": "medium",
  "diversity_policy": {
    "opening_3s_unique": true,
    "x_primary_asset_unique": true,
    "hook_text_unique": true
  }
}
```

然后 Variant Planner 根据这些参数规划 4 个变体。

---

## 3. Diversity Gate 检查时

Diversity Gate 会根据 policy 判断：

```text
开头 3 秒是否允许重复？不允许
主素材是否允许重复？不允许
Hook 文案是否允许重复？不允许
CTA 是否允许重复？允许
BGM 是否允许重复？允许
```

所以，默认配置会影响“哪些维度必须不同”。

---

## 4. 候选容量预检时

比如系统发现：

```text
batch_size = 4
x_primary_asset_unique = true
但可用主素材只有 2 个
```

就会提示：

```text
当前去重规则下最多只能生成 2 条有效差异变体。
```

这个判断也会用到默认配置。

---

## 5. 给菲律宾团队做“傻瓜式操作”

对运营来说，他们不用理解：

```text
opening_signature
render_intent_hash
batch ledger
asset cluster
```

他们只看到：

```text
菲律宾 TikTok Hook 测试模板
默认生成 4 条
系统自动避免重复
```

# 五、1.5 实施时建议怎么处理？

我建议你们这样拆。

## 第一阶段：先做通用默认 Policy

不要一开始就写成菲律宾专属。

先做一个全局默认：

```json
{
  "name": "default_matrix_policy",
  "batch_size_default": 4,
  "test_goal_default": "test_hook",
  "variation_strength_default": "medium",
  "diversity_policy": {
    "opening_3s_unique": true,
    "x_primary_asset_unique": true,
    "asset_cluster_unique": true,
    "hook_text_unique": true,
    "render_intent_unique": true,
    "cta_can_repeat": true,
    "bgm_can_repeat": true
  }
}
```

这就足够解决 1.0 的重复问题。

---

## 第二阶段：再加菲律宾预设

等通用能力跑通后，再加：

```json
{
  "name": "philippines_game_drama_ua_policy",
  "market": "philippines",
  "language": "taglish",
  "platform": "tiktok",
  "batch_size_default": 4,
  "test_goal_default": "test_hook",
  "variation_strength_default": "medium",
  "diversity_policy": {
    "opening_3s_unique": true,
    "x_primary_asset_unique": true,
    "asset_cluster_unique": true,
    "hook_text_unique": true,
    "render_intent_unique": true,
    "cta_can_repeat": true,
    "bgm_can_repeat": true
  }
}
```

这样它只是一个模板，不影响核心架构。

# 六、你们这次 1.5 的最小优先级应该是

按优先级排：

```text
P0：Variant ID / Batch ID / 独立 seed
P0：Render Intent Hash 去重
P0：Batch Diversity Ledger
P0：x_primary 主素材同批次不重复
P0：opening_signature 开头 3 秒不重复
P0：候选不足提示

P1：Matrix Lab 里显示测试目标和变体强度
P1：通用 default_matrix_policy
P2：菲律宾运营团队默认配置
```

所以第九点属于：

```text
P2：运营效率配置
```

不是：

```text
P0：防重复核心能力
```

# 七、最终确认

战友，这次 1.5 的主目标是：

> **解决“batch_size=4 生成 4 条一样视频”的问题。**

因此你们真正要做的是：

```text
Variant Planning
Diversity Gate
Batch Diversity Ledger
Render Intent Hash
Opening Signature
候选不足提示
```

“菲律宾运营团队默认配置”的作用是：

> **把这些防重复规则包装成菲律宾投手可以直接使用的一套默认 Matrix Policy。**

一句话总结：

> **防重复靠核心引擎，菲律宾默认配置只是调用这套引擎时的默认参数。1.5 可以先做通用防重复能力，再把它配置成菲律宾运营团队的一键模板。**
