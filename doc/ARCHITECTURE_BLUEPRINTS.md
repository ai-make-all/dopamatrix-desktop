## 💡 1. 延后音频混音架构 (Deferred Audio Muxing)

> **📅 记录时间**: 2026-03-24
> **✍️ 记录人**: DopaMatrix 核心架构组
> **🎯 预期版本**: V1.2 (Phase 4 混剪引擎升级)
> **🚧 实施门槛**: 【极高】需要精通 FFmpeg 的 `complex_filter` 拓扑图编译，以及处理音视频流在子进程中的同步时差问题。严禁不熟悉 FFmpeg 管道逻辑的 AI 或开发者随意修改此部分。
> **🚦 当前状态**: ✅ 已完成 (Merged in feature/v1.1)

**【背景】**
为了支持 Master-Variant (多语言变体) 架构，我们不能在第一步就生成带声音的视频。传统的并发渲染会因多音轨混合导致极大的 CPU 浪费与数据冗余。

**【实施策略】**
1. **静音母带生成**：主编译流 (`_build_filtergraph`) 只处理视频图层 (X/Y轴)，输出一条纯静音的母带 (`-an`)。
2. **变体延迟混音**：真正的混音发生在 `_render_variant` 中。槽位 `[0]` 永远是静音母带；槽位 `[1]` 优先分配给特定语言的 TTS (`voice_{lang}.mp3`)；槽位 `[2..N]` 分配给 Timeline 传过来的 BGM 和 SFX。
3. **BGM 降噪闪避**：通过判断 `audio_type == "bgm"`，强制注入 `volume=0.2` 滤镜，确保背景音乐不会掩盖 TTS 人声。最后使用 `amix` 将所有音频流合并。

> **📅 记录时间**: 2026-03-23

> **🚦 当前状态**: 📝 规划中 (Planned)

**【背景】**
打破单向的视听买量轰炸，实现“养成系互动错觉”。例如在 TikTok 故意投放失败的策略游戏广告，利用评论区的嘲讽反哺下一个变体视频的生成。

**【实施策略】**
1. **意图提取**：利用 NeuroFlow 大模型读取社交媒体评论（如“为什么踢飞 A 角色，让他站 C 位！”），提取出 `Target Entity` 和 `Action Intent`。

3. **情绪劫持机制**：在平台推流枯竭期，通过自动化水军 API 注入争议性评论，触发算法的“二次推流 (Resuscitation)”。

## 💡 3. AI 语音算力云端化部署原则 (The API Gateway Model)

> **📅 记录时间**: 2026-03-24
> **✍️ 记录人**: DopaMatrix 核心架构组
> **🎯 预期版本**: V1.5 (Phase 6 云端中枢)
> **🚧 实施门槛**: 【中】需要熟悉 FastAPI 的异步网络请求与第三方 API 鉴权，以及客户端积分扣减系统设计。
> **🚦 当前状态**: ⏳ 进行中 (In Progress)

**【架构红线】**
绝对禁止将重型 AI 语音模型（如 CosyVoice, ChatTTS 的权重文件和 PyTorch 环境）打包部署到客户本地！这会导致安装包体积膨胀至 5GB+，并引发无独立显卡客户机的崩溃。

**【实施策略】**
1. **端云算力解耦**：FFmpeg 的视频拼接和图层叠加全部在客户本地电脑执行，榨干本地 CPU；所有高质量 TTS 和意图推理，通过 API 方式调用远端服务器。
2. **多级路由网关**：在本地 `TTSNode` 中设计 Adapter 模式。
3. **SaaS 商业变现模型**：基础 Edge-TTS 提供免费无限量使用；需要高保真沙特男声或 CosyVoice 情绪嘲讽音效时，通过调用我们的云端 API 扣除用户账号的“算力积分 (Credits)”。

## 💡 4. 桌面端日志与监控演进架构 (Logging & Monitoring Evolution Strategy)

> **📅 记录时间**: 2026-03-24
> **✍️ 记录人**: DopaMatrix 核心架构组
> **🎯 预期版本**: V1.1 ~ V2.0+
> **🚧 实施门槛**: 【中】需要建立统一的 Logger 规范，并逐步引入端侧遥测机制。
> **🚦 当前状态**: ⏳ 分阶段演进中 (当前处于种子期)

**【架构决策】**
桌面端软件由于运行在物理隔离的客户机上，一旦发生崩溃，开发团队将陷入“黑盒”困境。因此，必须彻底摒弃传统的 `print` 调试，建立一套随软件生命周期动态演进的日志与监控体系，在不同阶段精准平衡“排障可见性”与“用户体验/性能”。

**【实施策略】**
本系统采用标准的“三阶段演进”模型：

1. **种子期 / 内测期 (当前 V1.1) —— 「明文日志 + 快速排障」**
   - **核心动作（增加可见度）**：深入底层所有节点（Nodes / Services），将 `print()` 彻底替换为标准 `Logger`。这是因为在 PyInstaller 的 `--windowed` 模式下，标准输出会被 NUL 设备吞噬，`print` 会导致报错瞬间“黑洞化”。
   - **业务闭环**：在客户本地以明文形式滚动写入 `.log` 文件。配合标准化的 GitHub Issue 模板，强制要求测试用户（如菲律宾营销团队）附带日志提交，实现跨国异步环境下的“见日志如见案发现场”。

2. **成长期 / 商业推广期 (V1.5 以后) —— 「日志降级 + 隐藏开关」**
   - **性能保护**：随着并发量的提升，将全局默认日志级别降级为 `WARNING` 或 `ERROR`。避免高频 `INFO` 写入导致的磁盘 I/O 阻塞和文件体积无限膨胀。
   - **排障后门**：在前端设置页或关于页面埋入“隐藏开关”（例如连击版本号 5 次），仅在特定用户遇到疑难杂症时，指导其开启 Debug 模式，动态唤醒全量底层日志。

3. **成熟期 (V2.0 以后) —— 「自动化遥测 + 诊断包导出」**
   - **被动转主动**：引入 Sentry 或类似端侧遥测 (Telemetry) SDK，当底层发生 `Traceback` 级严重崩溃时，自动脱敏并上报云端中枢，研发团队在客户感知前即可定位修复。
   - **一键体检**：在 UI 端提供“一键导出诊断包”功能。自动打包压缩 SQLite 疲劳度表（脱敏）、近 3 天 `.log` 文件及当前系统环境快照，生成加密 `.zip`，彻底消除客服沟通成本。

## 💡 5. 桌面端并发降维与 I/O 优化策略 (Concurrency & I/O Downgrade)

> **📅 记录时间**: 2026-03-24
> **✍️ 记录人**: DopaMatrix 核心架构组
> **🎯 预期版本**: V1.1 (Phase 4 渲染底座优化)
> **🚧 实施门槛**: 【中】需要深入理解 Python GIL 机制、SQLite WAL 模式与 PyInstaller Windows spawn 机制。
> **🚦 当前状态**: ✅ 已完成

**【架构决策】**
放弃纯计算密集型场景下的多进程 (`ProcessPoolExecutor`) 方案，全面转向多线程 (`ThreadPoolExecutor`) 与 WebSocket，规避打包后的跨进程通信死锁。

**【实施策略】**
1. **渲染层锁释放**：视频生成中的重负载为网络 I/O (LLM API) 与子进程 I/O (FFmpeg)。Python 线程在执行 `subprocess.run` 时会自动释放 GIL，多线程完全足以支撑底层多轨渲染的并发，且能将 60MB/Worker 的内存占用降至极限。
2. **轻量级双向通信**：放弃笨重的 Redis，利用 FastAPI 原生 WebSocket 实现生成进度条的高频回传。
3. **轮询防阻塞**：针对前端 3 秒状态轮询，后端强制开启 SQLite WAL (Write-Ahead Logging) 模式，实现读写分离互不干扰。

## 💡 6. 云-端-底 三层物理架构与 Webhook 闭环 (Cloud-Client-Core Architecture)

> **📅 记录时间**: 2026-03-24
> **✍️ 记录人**: DopaMatrix 核心架构组
> **🎯 预期版本**: V1.1 ~ V2.0
> **🚧 实施门槛**: 【高】涉及内网穿透、FastAPI 安全依赖注入及大文件流式传输。
> **🚦 当前状态**: ⏳ 进行中

**【架构决策】**
重资产云端管控与重算力边缘下放。平台采用 100% 平台无关 (Platform-Agnostic) 的 Webhook 异步回传设计，彻底解耦 Telegram/Discord 等业务端。

**【实施策略】**
1. **云端中枢层 (Cloud API Proxy)**：公有云网关保管所有高价值 API Key（LLM、高阶 TTS），保护账单安全并负责计费调度。
2. **业务外壳层 (Client Shell)**：本地 FastAPI 通过嵌入式 Ngrok (早期) / Cloudflare Tunnel (后期) 打通内网穿透，暴露接收端。通过注入 `X-Cloud-Token` 进行极简鉴权防扫描。
3. **引擎底座层 (Core Render)**：纯净的离线“打工人”。出片后，第二层通过异步 `httpx` 将视频文件字节流向第一层的 Webhook 地址进行 POST 结案报告。

## 💡 7. 桌面端“零信任”安全防护与环境解耦 (Zero Trust Desktop Packaging)

> **📅 记录时间**: 2026-03-24
> **✍️ 记录人**: DopaMatrix 核心架构组
> **🎯 预期版本**: V1.1.0-rc.1
> **🚧 实施门槛**: 【高】考验对 PyInstaller 与 Tauri 边车生命周期的深度掌控。
> **🚦 当前状态**: ✅ 已完成

**【架构决策】**
防范反编译与跨国机器的纯净环境（无 Python、无环境变量配置），实现开箱即用的“绿色”引擎。

**【实施策略】**
1. **Tauri Sidecar 机制**：臃肿的 AI 后端作为 `.exe` 边车运行，受 Rust 主进程严格管控，生命周期强绑定。
2. **物理路径智能嗅探**：通过 `sys.frozen` 嗅探打包状态，实现 `ffmpeg.exe` 在开发目录与 Tauri `bin/` 资源目录的自适应寻址，无视系统 PATH。
3. **零 CLI 工具依赖**：全面禁止通过 `subprocess` 调用第三方命令行工具（极易触发 `[WinError 2]`），强制使用纯 Python 包。
4. **敏感资产自毁**：打包环境下，Python 进程启动时自动扫描并 `os.remove` 同级残留的 `.env` 文件。
5. **BYOK 模式过渡**：在云端 Proxy Server 就绪前，采用前端输入 API Key 存入本地 SQLite 的方式（自带密钥），实现客户端包体的绝对去敏化。

## 💡 8. 智能素材库与标签化生命周期管理 (Smart DAM & Tagging Lifecycle)

> **📅 记录时间**: 2026-03-24
> **✍️ 记录人**: DopaMatrix 核心架构组
> **🎯 覆盖话题**: #10, #11, #14, #36, #37, #39, #53
> **🚦 当前状态**: ⏳ 迭代中 (待升级 AI 打标)

**【背景】**
单纯的随机混剪极易导致素材疲劳（Burn-out）和平台 pHash 查重封杀。传统的手工文件命名打标法无法支撑智能调度。
**【实施策略】**
1. **X轴物理隔离**：强制将库分为 `Hook` (黄金前3秒，决定80%点击) 和 `Body` (混剪骨料，承接信任)。
2. **AI 全维测序打标**：引入视觉大模型，素材入库即自动写入 SQLite 语义标签（`shot_type`, `emotion`, `scene`）。
3. **查重防封公式**：引擎内置算法安全阈值。$安全裂变上限 \approx (总片段数 \div 单视频需片段数) \times 3$。强控 Hook 片段复用率不超过 2 次。
4. **AI 变异车间**：对于疲劳值标红的实拍素材，调用 Video-to-Video 大模型进行风格迁移“洗白”，或调用图生视频生成极度夸张的 Hook（如：长城修电梯），突破实拍视觉枯竭。

## 💡 9. 测试优先的多语言与音画对齐管线 (Test-First & Audio-Driven Pipeline)

> **📅 记录时间**: 2026-03-24
> **✍️ 记录人**: DopaMatrix 核心架构组
> **🎯 覆盖话题**: #4, #9, #12, #30, #40, #55
> **🚦 当前状态**: 📝 规划重构中

**【背景】**
默认“1变3(多语种全渲染)”极度浪费本地算力与 API 成本，且无法进行精准的 A/B 归因测试。大模型对视频秒数缺乏物理概念，导致音画时长失控。
**【实施策略】**
1. **音频霸权主义**：废弃大模型指定的时长。视频 X 轴绝对总时长 = `TTS 真实物理时长 + 1秒缓冲`。到底层用 `-shortest` 极其干净地一刀切断画面。
2. **测试优先 (Test-First)**：引擎默认只渲染指定测试语言（如英文）的变体和无声 Master 母带。
3. **UI 时长强制枚举**：禁止用户在 Prompt 中自由输入时长，改为 `[短平快 15s]`, `[标准 30s]`, `[深度 60s]` 下拉框，后端通过系统级 Prompt 锁死大模型字数。

## 💡 10. 桌面端高并发降维与硬件感知预估 (Concurrency & Hardware Estimation)

> **📅 记录时间**: 2026-03-24
> **✍️ 记录人**: DopaMatrix 核心架构组
> **🎯 覆盖话题**: #26, #27, #29
> **🚦 当前状态**: ✅ 算法已确立，待 UI 接入

**【背景】**
C端低配电脑盲目全并发会导致死机。用户点击渲染后，干等 7 分钟缺乏掌控感。
**【实施策略】**
1. **排队与代理轻渲染**：本地采用后台异步任务队列。支持勾选“代理轻渲染”模式（输出 480x853 竖屏），将预览渲染时间压缩至 1 分钟内，定稿后交由云端高清化或夜间挂机渲染。
2. **动态耗时预估公式**：后端动态读取 CPU 核心数 $C$。基于公式 $E = \lceil B/C \rceil \times D \times k$ 计算预估耗时。
3. **自学习渲染系数**：每次任务完成后，引擎自动更新 SQLite 中的 $k$ (渲染消耗系数) 值，实现预估时间“越用越准”。

## 💡 12. 端云协同下的 Copilot/Autopilot 双模控制 (Copilot vs Autopilot)

> **🎯 覆盖话题**: #16, #24, #54, #70

**【实施策略】**

2. **双模指令下发 (WebSocket)**：
   - **Copilot (半手动)**：云端下发 [策略推荐卡片]，Tauri 桌面端或 TG Bot 弹出，用户点击 [一键装填] 授权执行。
   - **Autopilot (全托管)**：夜间免打扰模式，云端静默下发带 `is_autopilot: true` 的 JSON 负载，本地引擎自动唤醒渲染、产出、回传发布，次日生成战报。

## 💡 13. 微服务联邦与大模型技能调度 (Federated Microservices & Agent Skills)

> **📅 记录时间**: 2026-03-24
> **✍️ 记录人**: DopaMatrix 核心架构组
> **🎯 覆盖话题**: #15, #17, #21, #56, #58, #60
> **🚦 当前状态**: 📝 API 契约已构想

**【背景】**
非技术运营人员排斥复杂的连线式 Workflow。系统需要“聪明的脑”和“精准的手”。
**【实施策略】**
1. **代码联邦制**：dopamatrix 渲染引擎、GrowthOS 爬虫中枢必须分处不同的代码库，保护大模型的上下文窗口免受污染。

   为了极大降低第三方工具的接入阻力，对外的 API 必须封装得**与 OpenAI 的 ChatGPT API 格式完全一致**。客户只需将其代码中的 `Base URL` 替换为 `https://api.dopamatrix.com` 即可瞬间接入 NeuroFlow。
4. **专业 API 网关与计费拦截 (Gateway & Billing)**：
   大模型单次推理成本极高，接口禁止裸奔。必须在推理服务外层罩一个专业的 API 网关（如 Kong 或 APISIX）：
   - 为每个客户生成并校验独立的 `sk-xxxx` 密钥。
   - 实施严格的并发限流 (Rate Limiting) 防刷防 CC 攻击。
   - 实时拦截并统计出入 Token 数量，自动上报至云端 GrowthOS 扣除对应账户余额。

## 💡 22. 端侧抽帧与云端语义剪辑架构 (Frame-Scraping & Semantic Editing)

> **📅 记录时间**: 2026-03-30
> **✍️ 记录人**: DopaMatrix 核心架构组
> **🎯 预期版本**: V2.0 (Phase 8 视觉引擎)
> **🚧 实施门槛**: 【极高】需要精通 FFmpeg 的精准时间轴切割 (`-ss`, `-to`) 滤镜，以及多模态大模型处理超长上下文的时间戳对齐算法。
> **🚦 当前状态**: 📝 架构设计确立

**【背景】**
针对短剧、互动小说发行商，传统推广依赖人工预看全集并手动剪辑高光片段（Hook），耗时极长。若引入 VLM（多模态大模型）实现自动高光提取，面临致命的物理屏障：VLM 体积过于庞大，绝对无法打包进 Tauri 桌面端；而将几十 GB 的长视频原片上传至云端推理，将导致带宽挤兑与天价云端存储成本。

**【实施策略】**
采用“物理分离，端云协同 (Edge-to-Cloud Orchestration)”的极简架构：
1. **端侧剥离特征 (Local Feature Extraction)**：桌面端仅作为一个“特征提取器”。调用本地 FFmpeg 以 1 FPS 的极低频率将长视频转化为图片序列（Image Matrix），并提取极度压缩的音频流。此时 10GB 的视频缩减为 <10MB 的特征数据。
2. **云端语义解构 (Cloud VLM Inference)**：将特征数据发送至 GrowthOS。云端 Whisper 进行 ASR 转录，VLM 模型（如 Gemini/GPT-4o）结合画面与台词，定位剧情高潮、悬念转折，并输出包含精确起止时间（`start_time`, `end_time`）及情绪标签的 JSON 菜谱。
3. **本地物理切割 (Local Physical Trimming)**：桌面端引擎收到 JSON 菜谱后，利用 FFmpeg 的 `-ss` 与 `-to` 参数，在**本地未压缩的高清原片**上进行精准无损切割。
4. **最终组装**：切割出的高能片段，无缝进入现有的 DAG Workflow（添加 BGM、多语言字幕、互动按钮），完成极低算力成本的高清批量导出。
**【补充决策：端云算力分布边界 (The Local-ASR / Cloud-TTS Boundary)】**

1. **统一网关，绝对单例**：FastAPI 作为唯一的驻留进程启动，独占 8000 端口，并持有唯一的 SQLite 连接池句柄。
2. **算力隔离 (Dual Thread Pools)**：在 `services.py` 内部分配两个独立的 `ThreadPoolExecutor`：
   - `VideoExecutor`：调用 FFmpeg，应对低并发、极度消耗 CPU 的渲染任务。
   - `GraphicExecutor`：调用 Playwright (无头浏览器)，应对高并发、主要消耗 I/O 和内存的图文截图任务。
3. **安全并发**：无论前端提交多少种类的任务，后台通过不同线程池分流，即便视频渲染吃满 CPU，图文生成依然能秒级响应。
